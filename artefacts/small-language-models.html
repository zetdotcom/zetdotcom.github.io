Estimate the cost of routing requests

Take a month of traffic from one feature. How much of it would have to run locally to cover the cost of supporting a second model? The starting figures are an illustrative workload. Replace them with measurements or quotes for your own feature.

What the estimate includes

Hosted spend scales with the number of requests. Use the average hosted cost for this workload, including its typical input and output lengths. Mixed routing pays the fixed local cost plus hosted inference for the remaining traffic. Both local options assume the device capacity has already been sized for their workload.

The fixed cost can include hardware amortisation, energy, and support. If those costs change materially with volume, rerun the comparison with a different figure. Count a request as local only when it finishes without a hosted call.

Check the result against the product

Pick one request the local model got wrong. Would sending it to a larger model fix it, or does the app need to ask a question? Then try a supported request with the device offline. Those two tests help establish how much traffic can realistically stay on-device.
